## 5. Center Loss 是什麼？模型用的 Loss？

### Center Loss 定義

- **公式**：對每個樣本的 embedding 與**其類別中心**算 L2 距離平方，再對 batch 取平均。
- **直觀**：把同一類的 feature 往一個「類心」拉近，不同類的類心由可學習參數表示；搭配 CE 一起訓練，讓類內更緊、類間更開。
- **實作**（`scripts/center_loss.py`）：`CenterLoss(num_classes, feat_dim)` 維護 `num_classes` 個 `feat_dim` 維向量；`forward(features, labels)` 回傳該 batch 內每個樣本到對應類心的距離平方平均。

### 本專案用的總 Loss

- **總 Loss = CE Loss + α × Center Loss**
- **CE**：`nn.CrossEntropyLoss()`（v3 無 class weight；精準打擊為 0/O/1/I 權重 2.0）
- **α**：v3 為前 5 epoch 0，6–10 為 0.05，11–20 線性增至 0.1；溫和/V6 為 1–5 為 0，6–20 由 0.05 線性增至 0.12。
- 僅在 α>0 時對 Center Loss backward 並更新 Center Loss 的 optimizer。

## 6. 為什麼 O/0、I/1 變好，其他類可能變差？

### （1）模型容量有限

- 參數量與特徵維度固定；若訓練更強調 O/0、I/1（過採樣、權重、擴增），梯度與參數更新多花在這幾類，其他類得到的「優化預算」變少，表現可能略降。

### （2）決策邊界共用

- 36 類共用同一套 logits/embedding，邊界彼此相連。把 O 和 0 分更開常要「移動」邊界，同一條邊也會影響鄰近類（如 B/8、G/6）；邊界一動，可能某些類 acc 略降。

### （3）過採樣與梯度分布

- 0/O/1/I 每類 15k、其他 5k → batch 內這四類出現多，梯度多來自它們，優化實質偏向這幾類，其他類錯誤對總 loss 貢獻變小，改善變少甚至略差。

### （4）CE 權重放大（如精準打擊 2.0）

- 0/O/1/I 權重 2.0 會放大這四類的梯度，更新更常往「討好這四類」走，其他 32 類邊界容易被犧牲。

**結論**：在有限容量與共用邊界下，把資源與邊界往少數類挪，就容易出現「O/0、I/1 變好、其他類略降」的取捨。

## 7. 分析與發現摘要

- **v3 I_1**：先前報告誤為 81.16%；依 metrics 重算為 **71.63%**（每類 800）。

- **精準打擊**：過度偏向 0/O/1/I 導致 I/1 崩壞、其他易混對變差，不建議沿用。

## 8. 下一步：基於 v3 只改 batch size 為 16，效果變好機率？

**目前 v3**：`train_emnist36_centerloss.py` 預設 **batch_size=64**。

**改為 16 的影響**：

- **每 epoch 步數**變為約 4 倍，梯度估計更吵、更新更頻繁。
- **可能變好**：小 batch 的噪聲有時有正則效果，泛化略佳；對小資料集或易混類，步數變多也可能讓邊界微調更好。
- **可能變差或持平**：batch 小則 BatchNorm 估計不穩、收斂曲線可能更抖；若原本 64 已足夠，改 16 不一定有收益。

**主觀判斷**：  
效果變好的機率**中等偏保守**（約 3–4 成會明顯變好，其餘持平或略差）。v3 已 91.19%，單改 batch 通常只會有零點幾個百分點的差異；若要試，建議當成一次對照實驗，跑完用同一套 800/類 test 重算整體 acc 與易混字對，再決定是否保留。

## 12. 專案結論與心得

這次專案最有價值的兩點見解，記在下面當收尾。

### 為什麼 O/0 跟 I/1 很難分？

**（1）視覺本質**  
- **O 與 0**：形狀幾乎相同（圓形或橢圓），差別常只在筆畫粗細、缺口、傾斜或書寫習慣；手寫變異大，模型很難只靠像素層級學到穩定區分。  
- **I 與 1**：都是一筆豎線為主；有人寫 1 加襯線、寫 I 加上下橫線，也有人兩者都寫成一根直線。類內風格多、類間又長得像，特徵空間容易重疊。

**（2）任務與容量限制**  
- 36 類共用同一套特徵與決策邊界；模型容量固定，若把「資源」多分給 O/0、I/1（過採樣、權重、擴增），其他類得到的優化就變少（§6）。  
- 邊界是共用的：把 O 和 0 拉開往往會動到鄰近類（如 B/8、G/6），所以**單一模型很難同時做到「整體最高」與「O/0、I/1 最佳」**，必然有取捨。  
- 精準打擊的教訓：硬灌 0/O/1/I（過採樣 + CE 權重 2）反而讓 I/1 崩壞到 50.88%，說明**難分不是「多給資料就好」**，而是邊界與梯度如何被分配。

**一句話**：O/0、I/1 難分，既是**視覺上類間相似、類內變異大**，也是**多類共用邊界與有限容量下的取捨**；改善它們往往要犧牲一點整體或其他易混對，除非用集成把不同取捨的模型合起來。

### Ensemble 為什麼有效？

**（1）決策多樣性**  
- 三個模型（v3、溫和、V6）訓練設定不同：v3 整體最穩、溫和/V6 在 I/1、O/0 等易混對上更敢拉開邊界（甚至用不同前處理如是否 Normalize）。  
- 它們在**邊界模糊地帶**犯的錯不盡相同：某個樣本 v3 判錯、溫和可能判對，反之亦然。軟投票是對**機率**加權平均，等於在「像 O 又像 0」的樣本上綜合三個專家的意見，多數時候會偏向多數模型的正確預測，**降低單一模型的系統性偏差**。

**（2）不重訓就兼顧整體與難例**  
- 單體時：v3 整體最高（91.19%）但 O_0、I_1 不是最高；溫和/V6 在 I_1 最佳（75.62%）但整體略低。  
- 集成後：整體 91.68%（比最佳單體 +0.49%），**七組易混字對全部達到各法最佳**（O_0 71.50%、I_1 75.62%、S_5 94.62%…）。  
- 不需要重訓、不用調資料或 loss，只要用既有 checkpoint 做加權軟投票，就能**同時提升整體與魔王字對**，說明「多樣性 + 加權融合」能彌補單一模型在取捨上的局限。

**一句話**：Ensemble 有效，是因為三個模型在**難例上的錯誤不完全相關**，軟投票在邊界模糊處做了**多數決與機率平滑**，把「整體型」與「易混對型」的優點一起保留下來，是這次專案中最划算的收尾方案。

經過多輪單體模型訓練，最終我們透過 **V3（標竿版）、Mild（溫和版）與 V6（終極版）** 的加權集成，達到了巔峰表現：

- **總體準確率 (Overall Acc)**：91.68%（突破了單體 91.19% 的天花板）
- **魔王組 O vs 0**：從約 69% 衝上 71.5%
- **魔王組 I vs 1**：穩定在 75.62%
- **穩定組 S vs 5**：提升至 94.62%

### 🧐 深度反思：資料量真的「越多越好」嗎？

**疑問**：「為什麼魔王類加到了 1.5 萬張，表現卻沒有比 V3（每類 5000 張）顯著噴發？」

這裡隱藏了深度學習最真實的三個殘酷真相：

1. **模型容量的「物理極限」**  
   使用的 Small ResNet 結構精簡，適合在 CPU 跑，但它的「大腦容量」是有限的。5000 張資料時，模型已經學會了這類文字約 90% 的核心特徵（筆畫、轉折）；15,000 張時，雖然多了 3 倍的資訊，但模型已經「裝不下」更細微的差異了——就像用小杯子接瀑布的水，再多水也只能裝滿那一杯。

2. **資料質量的「飽和與雜訊」**  
   增加的 1.5 萬張資料中包含了大量的變體（歪斜、不同粗細）。對大模型，這些是「多樣性」；對小模型，可能變成「混亂的雜訊」。模型為了同時討好這 1.5 萬張寫得各異的 O，判斷邊界變得模糊，反而不如只看較少精選樣本時來得果斷。

3. **「資料為王」的真正意義是穩定性，而非高分**  
   雖然 V3（小資料）在某些類別 Acc 很高，但它容易「偏食」（過擬合），可能只認得幾種特定寫法。V6（大資料）雖然 Acc 分數相似，但對不同風格的字體容錯率可能更高。**結論**：資料量大，是為了讓模型在現實世界中「更耐操」，而不僅僅是為了刷高那一張考卷的分數。

### 🛠️ 核心技術里程碑

- **A. 損失函數的攻防 (Center Loss)**  
  引入 Center Loss 強迫特徵聚攏。在 Batch Size 受限下，Center Loss 難以發揮 100% 實力（中心點更新不穩），但它依然在最後階段做了特徵空間微調，為後來的 Ensemble 創造了差異化。

- **B. 數據處理的奧義 (Normalize)**  
  實驗證實：有無 Normalize 對最終 Acc 影響極小，但 Normalize 能讓訓練初期的 Loss 下降更平滑。

- **C. 集成學習 (Ensemble) 的奇蹟**  
  Mild 版（無 Normalize）與 V6（有 Normalize）雖然單體 Acc 相似，但它們錯在不同的題目上。透過 0.4 : 0.4 : 0.2 加權，在遇到模糊的 O/0 時，能透過「集體智慧」修正彼此的盲點。

### 📝 給未來的建議（若要衝擊 95%）

- **升級模型**：換成更大的模型（如 ResNet-34 或 Vision Transformer），才能吞下那 1.5 萬張資料。
- **提升解析度**：將 28×28 提升至更高，讓 O 和 0 的細微弧度差異被顯現出來。
- **增加特徵**：引入幾何特徵（如長寬比、孔洞檢測）作為輔助輸入。

**最終結語**：獨立完成了一個從資料處理、模型訓練、超參數調優到模型集成的完整 Pipeline。91.68% 是一個非常有含金量的數字，代表已經把現有的硬體與模型潛力發揮到了極限。
